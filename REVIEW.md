# Code review handoff

Review of `chart-sampler` against the Vercel React best-practices guide, August 4 2026.
Written for an agent picking up the fixes. Every finding below was verified by running the
code, not by reading it; the repro commands are included so you can confirm before and after.

## Context an agent needs first

This project has no React, no TypeScript, no bundler, and no dependencies. It is a static site
generator: `build.mjs` reads two JSON files, renders HTML strings through a tagged template in
`src/lib/html.mjs`, and writes `dist/`. The only code that reaches a browser is
`static/enhance.js` (78 lines) and the generated `dist/widget.js`.

Two consequences for anyone applying performance rules here:

- The `async-`, `bundle-`, `server-`, and `rerender-` rule families have nothing to attach to.
  There is no bundle, no hydration, no component re-render. Do not introduce a framework or a
  build step to satisfy them.
- Code under `src/` and `scripts/` runs once at build time over 19 data points. The `js-`
  performance rules do not apply there. Specifically, leave the multi-pass `Math.max`/`Math.min`
  in `src/lib/schema.mjs` and the repeated reduces in `takeaway()` alone; rewriting them trades
  clarity for nothing.

The project's purpose is to prove that data must be in the server's HTML response to be readable
by AI crawlers. Any change that moves a number out of the initial HTML defeats the point of the
repo. Treat that as the primary constraint.

## Priority 1: two verified bugs

### 1.1 `enhance.js` executes twice on the client-rendered variant

`page()` in `src/lib/layout.mjs:34` emits `<script src="enhance.js" defer>` whenever `script` is
not explicitly false. `src/pages/embed-script-tag.mjs` leaves it at the default, and the widget
generated by `buildWidget()` in `build.mjs:81-83` appends a *second* `enhance.js` after mounting.

Verified in the browser on `/embed-script-tag.html`:

```
script[src="enhance.js"]        2   (index.html: 1)
.card--chart .chart__tooltip    2   (index.html: 1)
.chart__dot                     38
```

Effects: two stacked tooltip divs that both position themselves on hover, 76 hover listeners
instead of 38, and `animateLines` running twice so the line re-animates from zero.

Maps to `client-event-listeners` and `advanced-init-once`.

Fix, both parts:

1. Set `script: false` in the `page({ ... })` call in `src/pages/embed-script-tag.mjs`. The
   widget already injects the script, and injecting it at runtime is the honest simulation of a
   third-party embed, so the widget is the one to keep.
2. Make `static/enhance.js` idempotent anyway, because nothing stops a CMS from placing the
   partial twice on one page. Add a guard at the top of the IIFE:

```javascript
if (document.documentElement.dataset.chartEnhanced) return;
document.documentElement.dataset.chartEnhanced = 'true';
```

Verify: rebuild, then confirm `/embed-script-tag.html` has exactly one `.chart__tooltip` per
`.card--chart` and that hovering a dot shows one tooltip.

### 1.2 One malformed URL kills the dev server

`scripts/serve.mjs:20` calls `decodeURIComponent` outside the `try` block, inside an async
request handler. A malformed percent-sequence throws, the promise rejects unhandled, and Node
exits.

Repro:

```bash
PORT=4399 node scripts/serve.mjs &
curl -s -o /dev/null -w "%{http_code}\n" "http://127.0.0.1:4399/%"   # server dies here
curl -s --max-time 3 http://127.0.0.1:4399/index.html                # connection refused
```

Output before the fix: `URIError: URI malformed` and the process terminates.

This matters because `npm run share` binds `HOST=0.0.0.0` for demos over LAN, so any stray
request or link prefetch can take the demo down.

Fix: move the `decodeURIComponent` and the path normalisation inside the existing `try`. The
`catch` already returns 404, which is the correct response for a malformed path. Do not add a
dependency or a framework for this.

Verify: rerun the repro above; the malformed request should return 404 and the server should
still answer the next request.

## Priority 2: the data table does not exist

This is the most important finding, because it undercuts the argument the repo exists to make.

Three places claim a data table ships in the HTML:

- `README.md` layout section lists `data table` among `src/partials/`.
- The `index.html` banner in `src/pages/index.mjs:24` says "The markup, the axis labels, and the
  full data table are all in the initial response."
- `src/pages/compare.mjs:36` repeats it, and `compare.mjs:140` recommends placing "the data
  table" into the CMS body as a fallback.

There is no table partial and no `<table>` on `index.html`. Confirmed:
`document.querySelectorAll('table').length === 0`.

`README.md` also states derived points are "flagged `"derived": true` and marked with an asterisk
in the rendered table", and `src/data/daily-sends.json` carries a `note` field that explains the
asterisk. Neither the asterisk nor the note is rendered anywhere. `dailySends.source` reaches
only the JSON-LD `creditText`; unlike the stats card, the chart card shows no visible source.

### Why this is substantive, not just a doc error

For 17 of the 19 days, the values exist only in `data-value` attributes on `<circle>` elements in
`src/partials/line-chart.mjs:66-75`. `dailySendsDataset` in `src/lib/schema.mjs:37-43` puts only
`maxValue` and `minValue` into the JSON-LD, not the individual points. So a crawler that strips
tags to text receives the two peak figures, which reach it through the takeaway sentences in the
SVG `<desc>`, and none of the other seventeen days.

Confirmed on the rendered page:

```javascript
document.querySelector('.card--chart').innerText.includes('1,013,302,698')  // false
```

That is a *published* figure for November 26, not a derived one.

The demo in `scripts/crawler-view.mjs` cannot detect this, because all seven entries in `PROBES`
target peak values, axis labels, or the JSON-LD wrapper. It reports 7 of 7 for the
server-rendered page and is technically correct while missing the gap.

### Fix

Build `src/partials/data-table.mjs` and include it in `sendsPerDayCard`. Requirements:

- A real `<table>` with a `<caption>`, `<th scope="col">`, and `<th scope="row">` for the date,
  matching the markup conventions already used by `matrix()` in `src/pages/compare.mjs:66-89`.
- One row per day with the value formatted by `withCommas()` from `src/lib/format.mjs`.
- Both series in the markup, hidden per-series by the existing
  `[data-series]` CSS rule in `static/components.css:102-105`, so the toggle keeps working and
  both channels stay in the HTML. This is the same pattern the chart and the stats card use.
- An asterisk on values where `point.derived` is true, plus a footnote rendering `data.note`.
- A visible source line for the chart card, mirroring `card__source` in
  `src/partials/peak-stats-card.mjs:26`.
- Styles added to `static/components.css`, which is part of the handoff artifact. Keep the
  existing token-based conventions and the section comment banners.

Then add a probe for a non-peak day to `PROBES` in `scripts/crawler-view.mjs`, for example
`{ label: 'Mid-window daily figure', needle: '1,013,302,698' }`. Before the table exists this
should report 7 of 8 for the server-rendered page; after, 8 of 8.

Finally correct `README.md`: the byte counts in the demo output block are stale. It claims 29,590
bytes for the server-rendered page; the actual current figure is 20,972. Regenerate that block
from a real run rather than editing the numbers by hand.

## Priority 3: browser payload, against the guide

All of these live in `static/enhance.js`. None are urgent at this scale. They are the patterns the
guide names, and they are worth doing because this file is part of the CMS handoff.

| Rule | Location | Fix |
| --- | --- | --- |
| `client-passive-event-listeners` | `static/enhance.js:56-59` | Add `{ passive: true }` to the scroll listener |
| `client-event-listeners` | `static/enhance.js:28-52` | Replace 38 per-dot listener pairs with one delegated `mouseover`/`mouseout` pair on the SVG |
| `js-batch-dom-css` | `static/enhance.js:40-42` | Two `getBoundingClientRect()` calls per hover force layout; cache the card origin and invalidate on scroll and resize |
| `js-batch-dom-css` | `static/enhance.js:62-71` | `animateLines` interleaves read, write, read, write per line; measure all lines, then write all |
| `js-cache-function-results` | `static/enhance.js:73-77` | `escapeHtml` rebuilds its replacement map on every character replaced |
| `rendering-svg-precision` | `src/lib/chart-math.mjs:33-36` | `xFor` is unrounded, so axis labels emit `x="187.16666666666669"`; round inside `xFor` as `linePath` and `points` already do |

Two of these interact usefully, so handle them together rather than separately:

**Delegation plus keyboard support.** Once the listeners are delegated, adding `focusin` and
`focusout` alongside `mouseover`/`mouseout` costs almost nothing. Today the tooltip is mouse-only
and the dots are not focusable, which sits oddly beside a toggle that was deliberately built to
be keyboard-operable (see the comment at `static/components.css:58-61`). If you decide the
tooltip should stay decorative because the SVG `<desc>` already carries the data in text, that is
a defensible call, but write it down in the file header instead of leaving it implicit.

**`textContent` instead of `innerHTML`.** `setupTooltip` rebuilds `tooltip.innerHTML` from
escaped strings on every hover. Build the tooltip once with two child spans and set `textContent`
on hover instead. That removes the per-hover HTML parse, and it removes the need for `escapeHtml`
entirely, which also resolves the duplicated escape table described below.

One more note on `static/enhance.js:67`: the bare `line.getBoundingClientRect()` is a deliberate
reflow flush between setting `strokeDashoffset` and transitioning it. Nothing says so, and it is
exactly the line a future reviewer deletes as dead code. Add a comment or restructure it with
`requestAnimationFrame`.

## Priority 4: conventions and hygiene

- `src/partials/line-chart.mjs:114` has `export { raw };`. Nothing imports `raw` from that
  module. Delete it.
- The escape table in `static/enhance.js:74-76` duplicates the one in `src/lib/html.mjs:11-17`.
  The duplication is structurally unavoidable across the build/runtime boundary, since
  `enhance.js` cannot import from `src/`, but switching the tooltip to `textContent` removes the
  need for the runtime copy altogether. Prefer that over adding a cross-reference comment.
- Style split: `src/` is modern ESM with `const`, arrow functions, `??`, and `.at(-1)`, while
  `static/enhance.js` and the generated `widget.js` are ES5 with `var` and an IIFE. That is
  defensible for markup pasted into an unknown CMS, but it is undocumented, so it reads as
  inconsistency rather than intent. One sentence in the `enhance.js` header comment settles it.
- `package.json` has no `engines` field even though `README.md` specifies Node 18 or newer. Add
  `"engines": { "node": ">=18" }`. There is no `license` field either.
- No Prettier or ESLint config, despite the code being formatted very consistently at roughly 100
  columns with single quotes and trailing commas. For a repo whose value is being handed to
  another team, pin the formatter so the convention is reproducible instead of living in one
  person's head. Add `.prettierrc` matching the existing style; do not reformat the codebase in
  the same change as a behavioural fix.
- No test script. A smoke test that runs the build and asserts every crawler probe still passes
  on the server-rendered variant would protect the exact claim the repo is built to make. This is
  the highest-value test to add and possibly the only one needed.
- The git repository has no commits yet, so none of this is version-controlled. Commit before
  starting.

## Suggested order of work

1. Fix 1.1 and 1.2. Both are small, both are verified, neither touches the argument of the repo.
2. Build the data table, add the non-peak probe, regenerate the README figures. Largest change
   and the one that matters most.
3. Rework `static/enhance.js` as one pass: idempotence guard, delegation, passive scroll, cached
   rects, `textContent` tooltip, batched animation reads, optional keyboard support.
4. Hygiene items, formatter config last and in its own commit.
